# sapsan-watch

Ловит подешевевшие билеты на «Сапсан» Москва → Петербург и пишет в Telegram.
Крутится на GitHub Actions, поэтому работает при выключенном ноутбуке.

Ничего не покупает и никуда не логинится — только читает публичную выдачу `pass.rzd.ru`.

## Что нужно сделать руками

1. **Завести бота.** В Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен вида `1234567890:AA...`.
2. **Узнать свой chat_id.** Написать [@userinfobot](https://t.me/userinfobot) — он ответит числом.
3. **Написать своему боту любое сообщение** — иначе Telegram не разрешит ему писать первым.
4. **Вставить секреты.** В репозитории: `Settings` → `Secrets and variables` → `Actions` → `New repository secret`:
   - `TELEGRAM_TOKEN` — токен из шага 1
   - `TELEGRAM_CHAT_ID` — число из шага 2
5. **Запустить вручную.** Вкладка `Actions` → `sapsan-watch` → `Run workflow`. Галка `debug` покажет сырой ответ РЖД в логе.

Дальше он сам просыпается каждые 10 минут.

## Настройки

Меняются в `.github/workflows/watch.yml`, блок `env`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `TRIP_DATE` | `20.09.2026` | Дата поездки, ДД.ММ.ГГГГ |
| `TIME_FROM` / `TIME_TO` | `09:20` / `09:50` | Окно отправления. Ловит все поезда, уходящие в этот промежуток |
| `PRICE_THRESHOLD` | `14000` | Ниже этой цены — громкий алерт |
| `DROP_DELTA` | `1000` | Тихий алерт, если цена упала хотя бы на столько с прошлой проверки |
| `PRICE_CEILING` | `30000` | Дороже — вообще не кандидат (отсекает первый класс) |
| `WANTED_CLASSES` | пусто | Коды классов через запятую, например `1Р,1С`. Пусто = все сидячие |
| `DAILY_DIGEST_HOUR` | `10` | Час по Москве, когда приходит сводка «что сейчас по ценам» |

## Что приходит в Telegram

- **Громкий алерт** — нашлась цена ниже порога. С номером поезда, классом, ценой, количеством мест и ссылкой на покупку.
- **Тихий алерт** — цена просто упала на `DROP_DELTA` и больше.
- **Сводка раз в сутки** — текущие цены по всем подходящим поездам, чтобы видеть, что бот жив.
- **Тревога** — если РЖД не отвечает шесть проверок подряд (примерно час).

Один и тот же алерт не повторяется чаще раза в час.

## Про места у окна

Скрипт подтягивает номера свободных мест и помечает те, что **похожи** на места у окна:
в ряду из 2+2 это первое и четвёртое, в 2+1 — первое и третье. Схемы «Сапсана» местами
не совпадают с этим правилом (столики, зоны у тамбура), поэтому номер в сообщении —
подсказка, а не гарантия. Перед оплатой сверься со схемой вагона.

## Про то, чего бот не может

Цены у «Сапсана» динамические: дешёвые тарифные корзины продаются первыми, и чем ближе
дата, тем дороже. Падения случаются в основном на **возвратах** — кто-то сдал билет, и его
корзина открылась заново по старой цене. Бот ловит именно такие окна. Гарантировать, что
они появятся, он не может.

## История цен

Каждый прогон дописывает результат в `state.json` и коммитит обратно в репозиторий.
Так что через пару дней там будет видно, как цена ходила.
